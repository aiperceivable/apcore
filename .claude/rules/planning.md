# Planning Directory Rules

This directory is **internal only** — never reference it in user-facing docs.

## Structure per feature
```
planning/<feature-name>/
├── overview.md       # Goals, scope, dependencies
├── plan.md           # Detailed implementation plan with task list
├── state.json        # Machine-readable progress tracking
└── tasks/
    ├── 01-task-name.md
    ├── 02-task-name.md
    └── ...
```

## state.json format
Generated by code-forge. Structure:
```json
{
  "feature": "<feature-name>",
  "created": "ISO-8601",
  "updated": "ISO-8601",
  "status": "pending|in_progress|completed",
  "execution_order": ["task-id-1", "task-id-2"],
  "progress": { "total_tasks": 7, "completed": 0, "in_progress": 0, "pending": 7 },
  "tasks": [
    {
      "id": "task-id",
      "file": "tasks/task-name.md",
      "title": "Human-readable title",
      "status": "pending|in_progress|completed",
      "started_at": null,
      "completed_at": null
    }
  ],
  "metadata": { "source_doc": "docs/features/...", "created_by": "code-forge" }
}
```

## Task files
- Named `kebab-case.md` (e.g., `context-key.md`, `builtin-steps.md`)
- Older features may use numbered prefixes (`01-handler-protocol.md`) — both are acceptable
- Each task file describes: goal, acceptance criteria, affected SDKs

## Dependencies
- Note inter-feature dependencies in `overview.md`
- Follow recommended implementation order from `planning/overview.md`
